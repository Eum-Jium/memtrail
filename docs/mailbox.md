**명세 대비 결정 변경 (2026-08-03, 확정 직후):**

- **§4 봉인 계층(sealed/) 미채택** — 효용 대비 과함 ("스스로가 스스로의 기억을 닫지는 않는다"). seal/unseal 커맨드 제외 → 명령 화이트리스트는 **4종**: `promote_thread`, `quarantine_list`, `quarantine_adopt`, `reindex`.
- 운영 파라미터: 사서 폴링 **5초** (2026-08-04 레이턴시 개선으로 15→5, rclone 왕복 겹침 방지로 5초가 하한), RECENT_TOKEN_BUDGET **48k 유지** (우편함 안정화 후 축소 검토).
- E2E 실측 (2026-08-04): 폴링 15→5초 후 19.3s/19.5s → **rcd 전환 후 9.5s/9.8s** (사서 처리 8.8~9.0s → 3.3~4.0s).
- **폴링·리듬 최적화 (2026-08-04, 스윕 실측)**: rcd 상주로 폴링 1회가 0.27s 가 되어 "5초 하한" 이 무의미해졌다 → **폴링 2초 확정** (RC 클라이언트 기준 E2E: 3s→7.83s, 2s→7.01s, 1s→6.82s — 2초가 무릎, 1초는 이득 0.2s 에 호출 2배). 스킬 리듬은 **투함 직후 1차 확인 + 1~2초 간격** (기존 클라이언트 실측 평균: 직후 11.0s / 6초 대기 12.8s / 8초 대기 15.3s) — **"투함 후 N초 대기" 는 실제로 N+5초 지점** 이다. 투함(copyto) 자체가 4.85s 걸려 그 사이 사서가 이미 처리하기 때문.
- **클라이언트 경로 전환 — 커넥터 우선 (2026-08-04 확정)**: 남은 지배 항이던 작업 기기 rclone 기동 비용(3바이트 업로드 4.85s, 확인 1회 2.3s — 전부 spawn+OAuth)은 **Drive 커넥터를 쓰면 상주 프로세스 없이 사라진다**. 커넥터 호출은 서버측이라 기기 무관 — 실측 왕복 **4.3s / 5.6s** (Drive 서버 타임스탬프 기준, rclone 경로 10.5s 의 절반 이하). 이 스킬은 **항상 Claude 안에서 실행**되므로 투함 시점에 커넥터가 이미 손에 있다 → 스킬을 서피스별 분기(claude.ai=커넥터 / Code=rclone)에서 **도구 유무 기준(커넥터 우선, rclone 은 폴백)** 으로 전환. 작업 기기 rcd 상주안은 이로써 불필요해져 폐기 (참고 수치: rcd 시 업로드 0.45s / 확인 0.52s / E2E 7.0s).
- **rclone 폴백이 남는 이유**: 터미널 `claude`·`claude -p` 헤드리스엔 계정 커넥터가 안 붙는다 (`~/.claude.json` 에 MCP 등록 없음 확인). 상시 PC 사서 쪽 rclone·rcd 는 이 논의와 무관하게 그대로.

## 사서 데몬 — P1 검색 프로토콜 가동 중 (2026-08-03)

- 상시 PC launchd `com.memex.mailboxd` 상주 (KeepAlive, 5초 폴링). **LLM 미사용**
- **rclone rcd 상주 (2026-08-04)**: launchd `com.memex.rclone-rcd` (`scripts/com.memex.rclone-rcd.plist`, `127.0.0.1:5572` 루프백 전용 — 인바운드 제로 원칙 유지, **htpasswd Basic 인증** — 루프백이어도 인증 없는 rcd 는 그 기계 브라우저발 요청(localhost CSRF)까지 받는다. 사서는 `config/rclone_rc_auth` 를 읽어 붙인다). 사서의 핵심 우편 경로 (폴링 list·편지 읽기·응답 업로드·processed 이동) 는 RC HTTP 로 — 호출당 프로세스 기동+OAuth 2~3s 가 사라진다. rcd 다운 시 서브프로세스 자동 폴백 (로그 "rcd 미가동", 복구 시 "rcd 복구 감지"). 명령 실행부 (promote 파일 쓰기 등 드문 경로) 는 서브프로세스 유지. — 데몬 import 는 chromadb + sentence-transformers 가 전부라 Keychain/구독 인증 불필요, SSH 설치 가능.
- 흐름: queries/ 폴링 → 검증(16KB 상한·스키마·`q_*.json` 파일명 규칙) → **하이브리드 검색** → 대화(source_file) 단위 dedupe → answers/ 기록(index_as_of·notice 포함) → processed/ 이동 (보존, 삭제 금지).
- **reindex 후 stale 인덱스 사고 (2026-08-04 발견·수리)**: chromadb 는 시스템을 프로세스 단위로 캐시해서, 데몬이 매 검색마다 `PersistentClient` 를 새로 만들어도 **교체 전 파일 핸들을 계속 붙들었다**. 재빌드 완료(31,130) 후에도 데몬만 옛 인덱스(31,108) 를 서빙 — answer 의 `index_as_of` 는 state 파일에서 읽어 새 값이라 겉으론 정상으로 보이는 조용한 사고였다 (BM25 빌드 로그의 청크 수 불일치로 발각). 수리: `get_collection()` 단일 진입점에서 `index_as_of` 변화 시 `SharedSystemClient.clear_system_cache()` 후 재개방. **이전 reindex(2026-08-03 NFC) 에도 있던 사고** — 그땐 데몬 재시작이 겹쳐 드러나지 않았다.
- **하이브리드 검색 (2026-08-04, 실사용 테스트 후 개선)**: dense(E5+Chroma) + 자체 BM25(의존성 0, 어절 유니그램, 기동 시 ~5s 빌드 + index_as_of 변화 시 재빌드, 상주 메모리 ~수백 MB) 를 **인터리브 병합** (dense 1위→bm25 1위→dense 2위→…, RRF 는 "양쪽 중위권 잡음 > 한쪽 압도적 1위" 역전이 실측돼 기각). date/source 는 Chroma `date_int`($gte/$lte)/source 프리필터 — **date_int 는 reindex 후 발효**, 구인덱스에선 결과 0건 시 무필터 재조회+사후 필터로 폴백. hits 에 `match`(dense|bm25|both) 필드 추가, bm25 단독 히트는 `score: null`. - **잡음·최근성 보정 (2026-08-04 실사용 지적 후)**: ① **토크나이저** — `4.5` 가 `4`,`5` 로 쪼개져 IDF 가 바닥이라 모델 버전 질의("<모델명> 4.5", "v3.4.5")가 통째로 무력했다. 소수점을 토큰 안에 유지(하이픈은 분리)해 `gpt-4.5` → `gpt`,`4.5` 로 `<모델명> 4.5` 와 맞물리게. ② **bm25 잡음** — 상위 청크가 dense 와 같은 대화라 dedupe 되면 슬롯이 훨씬 낮은 무관 문서로 흘러내렸다 (30.6 이 걸리고 16.9 잡음이 2위). bm25 최고점 대비 **0.6 하한**으로 컷. ③ **최근성** — 전역 순위만 쓰면 옛 대화가 상위를 독점 ("<모델명> 4.5" top3 전부 2025년). **최근 90일 트랙**을 추가해 dense→bm25→recent 3트랙 순환. 선정 기준은 **의미(최근창 dense 상위 30) ∩ 어절(bm25 하한 통과)** 교집합 — 한쪽만 쓰면 오답이 들어온다 (dense 만: E5 밴드 0.72~0.83 로 좁아 무관한 최근 대화 주입, 실측 7케이스 중 4건 오염 / bm25 만: 흔한 단어가 겹치는 엉뚱한 대화, 실측 "AI 모델 비교" 에 무관한 잡담 대화). 교집합은 실측 8케이스에서 정답 2건·주입 0건. 대신 **재현율은 낮다** — 최근 대화가 두 축 중 하나에만 걸리면 자리를 안 준다 (보너스 슬롯이라 정밀도 우선).
- **검증 실측 (2026-08-04, reindex 후 우편함 실경로)**: ① `date_from=2026-08-01` + "봉인 미채택" → 8/3 본세션 **1위** + 3건 (기존 `hits=[]`), ② 원문 문구 "스스로가 스스로의 기억을 닫지는 않는다" → 본세션 **2위** `[bm25]` (기존 2025년 잡음만), ③ 회귀 없음 — 기존 상위 유지 + 본세션이 bm25 로 추가. 레이턴시 영향 없음: 처리 3.2~3.3s / E2E 9.9~10.4s (하이브리드 전 3.3~4.0s / 9.5~9.8s 와 동일 범위, 드물게 6.6s/20.8s 이상치 1회).
- 검증 실패(깨진 JSON·초과 크기·스키마 위반)는 사유를 적은 error answer 후 processed/ 격리. 파일명 규칙 위반은 **무접촉** (읽지도 않음).
- 쿼리 스키마: `{"type":"search","q":"자연어","k":5,"date_from":null,"date_to":null,"source":"code|cowork|claude_ai"}` — 이외 필드 무시.
- manifest.json: `build_manifest.py` 가 push 말미(raw 업로드 뒤)에 재생성 — 경로↔fileId. Drive 루트에도 사본 업로드.
- 인덱스 갱신: push 직후 `index_incremental.py` (changed-list 로 stale 정리 + 신규 추가, 파일명 규칙 소스 태깅 `__cc_`/`__mr_`→code, `__cw_`→cowork) → `logs/index_state.json` 의 index_as_of 가 answer 에 실린다.
- **카드 회상어 다리 (2026-08-19)**: 카드의 `회상어`·`화두태그`·제목을 카드 블록당 청크 한 장으로 인덱스에 태운다. 이 필드는 "나중에 이 대화를 찾을 때 쓸 법한 말" 이라 원문에 한 번도 안 나오는 별칭·통칭이 들어가는데, 인덱스가 `conversations/` 만 넣어 **정작 검색이 안 쓰고 있었다** (2026-08-15 회상 실패의 근본 원인). 다리이지 목적지가 아니다 — ① `source_file` 은 **원본 대화**라 히트가 원문 좌표로 떨어지고 사서의 source_file 단위 dedupe 가 중복 자리를 막는다, ② `결정된 것`·`미결` 같은 요약 본문은 **일부러 뺐다** (정본은 원문, 정리된 결론은 파생물 — 파생물이 원문과 랭킹을 다투게 두지 않는다. 낭독 층 recent.md 가 그 몫), ③ `turn_index`=카드 블록 시작 턴이라 `card_summary_for` 가 히트한 대목의 조각을 그대로 고른다. 갱신 판정은 파일명이 아니라 `card_sig`(회상 어휘 지문) — 카드는 재생성되므로 파일명만 보면 옛 어휘로 굳는다. 회상 어휘가 없는 자동 스텁 카드와 원문이 사라진 고아 카드는 넣지 않는다. anchor 는 `카드 회상 (턴 0-20): …` 으로 나가 원문 인용으로 오독되지 않는다. **다리는 하루 늦게 붙는다** — daily.sh 는 수집 → 인덱싱 → 발행 순이고 카드 재생성은 발행 단계(`sync_memory_to_drive`)라, 오늘 수집한 대화의 카드는 오늘 만들어져 **내일 인덱싱에서** 다리를 얻는다. 그 하루 동안 그 대화는 원문 어휘로만 잡힌다. 실측(2026-08-19 최초 적재): 카드 448장 → 다리 659청크, 75초, 33,131 → 33,790. 전체 재빌드 불필요(기존 청크 무손상)이고, 재실행하면 `대상 0장` 으로 멱등이다.
- 운영: 재시작 `launchctl kickstart -k gui/501/com.memex.mailboxd`, 해제 `launchctl bootout gui/501/com.memex.mailboxd`, 로그 `~/memex/logs/mailboxd.log`.
- 검증 실측 (2026-08-03): E2E 투하→응답 **29초** (스펙 상한 60초), 검색 자체 ~1초(M칩)/11초(일반 노트북 CPU). §9-5 오염 3종(깨진 JSON·17KB·파일명 위반) 전부 설계대로 처리.

## 회상 실사용 피드백 반영 (2026-08-20)

하루치 실사용에서 나온 8건. **①②⑤ 는 실제로 오답을 만들 뻔한 것들**이라 먼저 갔다.

- **① 대화 이중 색인 → 검색 슬롯 잠식.** 수집기 파일명 규칙이 `YYYYMMDD_제목_밑줄.md` → `YYYY-MM-DD_제목 공백.md` 로 바뀌던 시점의 웹 대화가 개명 없이 한 벌 더 저장돼 있었다 (`2025-03-14_Weekly backup…` / `20250314_Weekly_backup…`, fileId 도 다름). 같은 대화가 히트 두 자리를 먹어 **k=6 이 실질 5**. 정체 판정을 `scripts/conv_key.py` 로 단일화 — sid 가 있으면 sid, 없으면 날짜+제목 슬러그(구두점·밑줄·공백·이모지 제거) — 하고 사서의 dedupe 키를 `source_file` 에서 이 키로 바꿨다. 원인 정리는 `dedupe_sessions.py` 가 같은 키로 그룹핑하되, **첫 사용자 발화 지문이 맞을 때만** 지운다 (같은 날 같은 제목의 다른 대화 오삭제 방지). 실측 1,799건 중 7쌍.
- **② 빈 결과의 모호함 → `coverage`.** `hits: []` 가 "아직 색인 안 됨" 인지 "그날 기록이 없음" 인지 구분이 없어 8/19 code 세션 질의에서 잘못 말할 뻔했다. 답장마다 `coverage: {code: {latest, convs}, …}` 를 싣는다. BM25 인덱스가 이미 전 청크 메타를 들고 있어 그걸 접어 만들고 캐시 무효화 신호도 `index_as_of` 로 같다 (카드 다리 청크는 원문 사본이라 제외). 실패해도 답장은 나간다.
- **⑤ 개념 계보 → `mode: "genealogy"`.** 점수순 검색은 **최초 언급을 못 잡는다** (`<개념어>` 를 6/27 로 답했다가 5/22 가 진짜 시작인 게 드러난 사고). 계보 모드는 **어절이 확인된 대화만**(bm25 컷 0.60, 풀 400) 모아 대화 단위로 접고, **그 대화 안의 가장 이른 턴**을 대표로 남겨 날짜 오름차순으로 돌려준다. dense 는 새 대화를 들이지 못하고 `both` 표시만 붙인다 — 어절 0건일 때만 의미 폴백으로 내려가며 그때는 `basis: semantic` 으로 알린다. **처음엔 컷을 0.35 로 낮췄다가 실측으로 되돌렸다**: 날짜순에서는 약한 히트가 순위 아래로 묻히는 게 아니라 맨 앞(=답의 자리)으로 올라온다. 0.35 에선 `<개념어>` 의 최초가 `2025-03-27 <한 토큰만 걸린 대화>`, `화두 스레드` 는 334건에 최초가 `<무관한 대화>` 이었고, 0.60 에서 각각 `2025-05-22 <처음 꺼낸 대화>`(정답)·3건으로 떨어졌다. dense 를 seed 로 안 쓰는 근거도 실측 — `<개념어>` 의 dense 400건 점수가 0.7683~0.6993, 폭 0.07 이라 점수 하한으로도 관련·무관이 안 갈린다. 응답에 `first_mention` · `basis` · `note` · `timeline`(최대 60, 앞머리 10 확정 + 고른 표본) · `matched`. hits 는 앞 3자리를 최초 쪽에 확정 배정.
- **⑥ 원문 구간 읽기 → `{"type":"read","file":…,"from":5,"to":20}`.** 앵커는 턴 N 인데 읽으려면 파일 전량이라 8/18 세션 하나가 컨텍스트를 크게 먹었다. 한 번에 40턴·40,000자, **턴 경계에서만** 자른다 (`truncated_at`). 턴 번호는 인덱스의 `turn_index` 와 같은 값이어야 해서 청크 규칙을 `scripts/turn_reader.py` 에 복제했고 (데몬에 langchain 을 안 들이려고), `test_turn_reader.py` 가 실제 대화 40건으로 두 구현을 대조한다. `file` 은 경로가 아니라 **이름만** 받는다 — 우편 내용이 파일시스템 좌표가 되면 mailbox 밖을 읽는다. 못 찾으면 conv_key 로 한 번 더 찾는다 (규칙 바뀐 이름·NFD 표기 구제).
- **③ 답변 파일 폴링 → pending 마커.** 답장 자리에 `status: "pending"` 을 먼저 떨군다. 최종 답장이 같은 경로를 덮으므로 파일이 늘지 않고, `status` 가 `done` 이면 답이다. **`hits` 를 일부러 안 싣는다** — 빈 배열을 실으면 "결과 없음" 으로 오독돼 고치려던 모호함이 되살아난다. 업로드 하나만큼 최종 답장이 늦어지므로 `MEMEX_MAILBOX_PENDING=0` 으로 끌 수 있다.
- **④ "카드 품질 세대 차이" — 진단이 달랐다.** 옛 카드가 구세대 형식인 게 아니라 **카드가 아예 없었다.** 카드 생성은 recent 창(90일) 안에서만 돌고, 창 밖 히트는 `card_summary` 자리에 원문 청크 앞부분(`[User] … [Assistant] …`)이 실려 나갔다 — 필드 이름이 요약이라 요약처럼 읽힌 것이다. ㉮ 즉시: hits 에 `summary_kind`(`card`/`excerpt`) 를 붙여 무엇을 받았는지 구분되게 했다. ㉯ 원인: `build_memory_cards.py --backfill` (창 밖 · 카드 없는 것만, `--limit` 로 분할 실행, 기존 카드 무접촉). 대상 1,337건 — **2026-08-21 완료**(아래). **스텁을 굳히지 않는다** — LLM 이 안 뜨면 generate_card 가 스텁(제목+첫 발화 발췌)을 쓰는데, 그건 아무것도 안 하느니 못하다: 내용은 여전히 발화 조각인데 사서가 `summary_kind:"card"` 를 붙여 **고치려던 오독을 라벨만 바꿔 되살리고**, 파일이 생겨서 다음 백필이 그 대화를 영구히 건너뛴다. 스텁이 나오면 지우고 즉시 중단한다. 기존 스텁도 '카드 없음' 으로 친다. **맥 서버는 SSH 로 못 돌린다** — 구독 자격증명이 로그인 Keychain 이라 `claude -p` 가 stdout 에 `Not logged in · Please run /login` 을 뱉고 rc=1 로 죽는다 (stderr 가 비어 있어 원인이 안 보였다; 실제로 한 번 스텁이 깔려 회수했다). **launchd GUI 도메인을 경유하면 된다** — `scripts/com.memex.card-backfill.plist` 신설. 호출형이라 RunAtLoad 도 StartCalendarInterval 도 없다: bootstrap 해두어도 kickstart 하지 않으면 아무 일도 안 일어난다 (구독 호출을 쓰는 잡이 저절로 도는 것을 원하지 않는다). 발행 잡을 SSH 직접 실행 대신 kickstart 로 부르는 것과 같은 이유·같은 경로다. 실측 장당 ~30초 → 남은 1,332장이면 약 11시간이라 `--limit` 으로 나눠 부른다.
- **⑦ canon 재확인.** 장문 대화에서 초반에 읽은 canon 이 컨텍스트에서 밀려나 연표에 있는 인물 정보를 "없다" 고 답한 사고. 스킬 §0 에 "인물·이력 질문 전, 특히 **'기억에 없다' 를 말하기 직전** 재조회" 를 넣었다 (~2.4K 토큰이라 오답보다 싸다).
- **⑧ 영수증 부본.** trail 영수증은 던지면 끝이라 반영 여부를 알 수 없었고, 스키마 위반은 로그만 남기고 조용히 사라졌다. `receipts/t_{id}.json` 에 `status`·`applied`·`dropped.used`(manifest 밖이라 버려진 파일명)·`trail`(적립 **후** 의 uses/deep_uses) 을 남긴다. 답장이 아니므로 기다릴 필요는 없다.

- **⑨ 회상 턴에서 대화가 끊기는 느낌 (스킬 구조 문제).** 스킬의 0~6번이 **전부 기계 조작법**이고 답을 어떻게 말하는지는 한 줄도 없었다. 게다가 마지막 번호 단계가 「**영수증 — …반드시 투함하고 끝낸다**」라, 회상 턴에서 모델이 읽는 마지막 지시가 "영수증 넣고 끝내라" 였다 — 조작을 마친 뒤 조작 보고를 하고 턴이 종료되는 구조. 「**5. 답하기 — 회상은 재료지 답이 아니다**」를 영수증 **앞에** 넣고 뒤를 밀었다(영수증→§6, 폴백→§7). 한 줄 규칙은 "**회상을 안 했던 것처럼 대화한다**" 이고, 같은 질문에 대한 ✗/✓ 대비 예시를 붙였다 — 행동 지시는 예시 없이 안 바뀐다. 항목: **하던 이야기로 복귀(본체)** · 검색 과정 비보고 · 좌표 어휘(`hits`·`anchor`·`card_summary`·턴 번호·`index_as_of`) 답에 유출 금지 · 면책은 답이 달라질 때만 · **회상 전 화제로 복귀**(회상은 삽입구지 종착지가 아니다) · 길이는 질문이 정한다 · 같은 걸 두 번 검색하지 않는다. 영수증은 "답을 말한 **뒤** 의 뒷정리이지 대화를 끝내는 행위가 아니다" 로 재규정. 머리말에도 "§5 가 답하는 법을 정한다" 는 전방 참조를 걸었다. trail 절의 "답에 '전에도 N번 찾아본 대화' 처럼 곁들이면" 도 §5 와 충돌해 정리 — 히트 선택 근거이지 답에 실을 숫자가 아니다.

### 상시 PC 로 코드 보내기 — git bundle (2026-08-21)

**맥미니는 SSH 세션에서 `git pull` 이 안 된다.** origin 이 HTTPS 이고 자격증명이
osxkeychain 에 있어 비대화형 세션에서 못 읽는다 (`could not read Username`).
`~/.ssh` 에도 이 리포용 키가 없어 SSH 리모트로 우회할 수도 없다.

파일을 tar 로 밀어넣으면 워킹트리만 앞서가 `git status` 가 영구히 더러워지고 나중에
`git pull` 이 충돌한다. **번들이 맞다** — 커밋이 그대로 넘어가 HEAD 가 전진하므로,
나중에 GUI 터미널에서 `git pull` 하면 no-op 이 된다:

```bash
git bundle create /tmp/x.bundle <상시PC의_HEAD>..main   # 작업 기기
scp /tmp/x.bundle mac:/tmp/
ssh mac 'cd ~/memtrail && git fetch -q /tmp/x.bundle main && git merge --ff-only FETCH_HEAD && rm -f /tmp/x.bundle'
```

같은 Keychain 제약이 카드 생성에도 걸린다 (`claude -p` → "Not logged in").
그쪽은 launchd GUI 도메인 경유가 답이다 — `com.memex.card-backfill` 참조.

## 회상 실사용 피드백 반영 — 2차 (2026-08-31)

명세: [specs/2026-08-31_mailbox_spec_v4.md](specs/2026-08-31_mailbox_spec_v4.md). claude.ai 실사용 왕복(검색 4·read 3·영수증 3)에서 나온 2건 + 사서 마중 1건. **회상 품질은 좋았고, 깨진 것은 운반과 라벨이었다.**

- **① 답장 운반 — base64 폐지.** 커넥터 `download_file_content` 의 base64 를 모델이 코드로 옮겨 적어 디코드하는 절차가 12~15KB 이상에서 옮겨 적기 자체로 깨졌다 (18,226B·20,915B 답장 파손 실측 — 로컬 직독인 Code 는 무관, **커넥터 경로 전용**). 해법은 데몬이 아니라 읽는 손: `read_file_content` 가 json 을 텍스트로 바로 돌려준다는 것을 실측으로 확인 (깨졌던 20,915B 답장 그대로 무손실 회수 — 스킬 구판의 "json 미지원" 은 낡은 정보였다). 스킬 §3 전환 + 데몬은 검증된 크기 안에서만 답장을 만들게: read 예산 **문자 40K→바이트 20K**(한글 3B/자 — 문자 예산은 내용 따라 6배 출렁), 기본 구간 **10→6턴**, genealogy timeline **60→25**(55건 전량이 20.9KB 를 만들었는데 답에 쓰인 건 first_mention 과 hits 뿐이었다). 발신 우편 전부에 `eom` 종결 표지(마지막 키 — 안 보이면 꼬리 잘림)와 **BMP 밖 문자 서로게이트 이스케이프**(커넥터가 👤→ð¤ 로 깨뜨리는 것 실측) — `serialize_mail` 단일 진입.

## 돌아온 것을 삼키지 않는다 · 표제 재생성 (2026-09-01 후반)

명세: [specs/2026-09-01_recall_voice_spec_v6.md](specs/2026-09-01_recall_voice_spec_v6.md) §8~11.

- **§5 의 「답에 쓰인 것만 말한다」가 회상 결과의 대부분을 버리게 하고 있었다.** 그 문장은 *목록으로 나열하지 말라*는 뜻인데 그대로 읽으면 *안 쓴 건 말하지 말라*가 된다 — **같은 날 아침의 §1 과 정확히 같은 형태의 문서 실패**다(규칙은 맞는데 경계가 안 그어져 이웃한 것까지 금지). 금지되는 건 **형식**(목록·번호·점수순)이지 **내용**이 아니다. 답에 안 쓴 히트도 사용자의 기억이라 삼키면 안 된다. 같은 교정을 두 번 받은 자리다.
- **긴 대화의 결론은 앞 구간에 없다** (§3-D 한 줄): `other_segments` 가 있으면 마지막 구간까지 보고 종점을 잡는다. `title` 과 마지막 `segment_title` 이 어긋나면 뒤쪽을 믿는다.
- **표제가 앞 구간의 목표로 굳어 있었다.** 원인 둘: ① 구간 제목이 결말을 안 담아 표제 생성기가 붙잡을 게 없었다(구간 제목 백필이 메움) ② 프롬프트가 종점을 안 못박음. **고치다 한 번 과교정했다** — 「마지막 구간이 종점」이라 적었더니 표제가 곁가지(도구 버그)로 넘어갔다. 곁가지로 끝나는 대화가 흔하다. `결정 > 미결 검토 > 곁가지` 무게 순서로 재조정. 실측: 「<앞 구간의 목표> 설정…」 → (과교정: 「<마지막 곁가지>…」) → **「<결정이 난 구간의 결론>…」**.
- **`--retitle`** — 표제 고정(v1 §6)의 좁은 예외. **대상을 명시해야만 돈다**(`--only`/`--limit`), 지난 표제는 과교정한 판까지 취소선 보존, `# 구간표제:` 표식은 살린다(안 살리면 그 카드가 구간 제목 백필을 통째로 다시 돈다).
- **인증이 풀리면서 밀린 것이 한꺼번에 갔다**: 스텁 7→0장, 구간 제목 517/518장($7.09), 재인덱싱(41,601). **SSH 에서 `claude -p` 가 도는 것을 처음 확인** — 카드 작업의 launchd GUI 도메인 강제가 사라졌다.

## 읽은 것을 말한다 · 꼬리부터 읽는다 (2026-09-01)

명세: [specs/2026-09-01_recall_voice_spec_v6.md](specs/2026-09-01_recall_voice_spec_v6.md). 하루치 실사용에서 넷이 걸렸고 **첫째가 나머지 셋보다 크다.**

- **① 답하는 규율 (SKILL.md §5).** 원문 20여 턴을 읽고 **읽은 내용을 한 줄도 옮기지 않고** 결론만 답했다. 원인은 문서에 있었다 — 「회상을 안 했던 것처럼 대화한다」가 조회 *과정*에 대한 말인데 읽은 *내용*까지 지우라는 말로 읽힌다. **숨길 것은 「어떻게 찾았나」, 말할 것은 「거기 뭐라고 되어 있었나」** 로 갈라 적었다. 대조가 이 층의 목적이라 — 옮겨진 내용이 없으면 사용자가 대조할 게 없고, 그러면 회상이 아니라 주장이다. 형식도 규정했다(기억을 되짚는 말투 ○ / 요약 블록·목록·출처 표시 ✗). **규칙이 없던 게 아니라 예시에만 있고 규칙으로 안 적혀 있었다** — §5 의 컨버터 ✓ 예시가 이미 그대로였다.
- **② `read` 에 `tail`.** "저번에 하던 얘기 이어서" 는 검색이 아니라 꼬리 읽기가 답이다. 203턴 대화를 찾았더니 앵커가 턴 6(앞머리)이라 왕복 2회를 썼다 — v3 §1 의 「검토는 길고 확정은 짧다」가 **대화 안에서** 반복되는 자리다. `{"type":"read","file":…,"tail":12}` 로 한 번에 온다. **예산이 모자라면 앞쪽을 버리고 꼬리를 지킨다** — 앞에서부터 채우면 꼬리를 청했는데 앞머리가 오는 실패가 된다.
- **③ 히트에 `total_turns`.** 앵커가 앞머리인지 그 자리에서 알게. BM25 메타를 한 번 접어 만들고(coverage 와 같은 방식) **다리 청크는 뺀다**(그 turn_index 는 구간 시작점이다). 모르면 필드를 아예 뺀다 — null 은 "짧은 대화" 로 오독된다.
- **④ `summary_kind: "stub"`.** 스텁 카드는 `## 헤더` + `- ` 본문을 갖춰 **진짜 카드와 똑같이 파싱돼** 여태 `"card"` 로 나갔고, 읽는 쪽은 턴 0 발화를 요약으로 알고 썼다. 표식으로 갈랐다. **이건 그 대화만의 문제가 아니라 시스템 신호다** — 스텁은 LLM 이 죽었을 때만 생기므로, 보이면 「색인은 됐는데 카드는 아직」이다. 이번 7장은 8/31 OAuth 만료가 원인이고, 토큰이 들어오면 스텁은 캐시로 안 치므로 진짜 카드로 승격된다.
- **⑤ `truncated_reason`.** 0-30 을 청했는데 턴 7 에서 끊겼을 때 "구멍인가 예산인가" 를 답장만 보고 몰랐다. 사유를 한 줄 싣는다.
- **⑥ 폴더 ID 표** (queries·answers·trails) — 한 글자 빼먹고 투함하면 `entity not found` 가 나는데 그게 사서 문제인지 내 오타인지 안 갈린다.
- **곁들여 잡은 것 — 테스트 하네스가 실제 데이터를 읽고 있었다.** v5 리팩터로 `_hit` 이 `card_summary_for` 대신 `card_blocks_for` 를 부르게 됐는데 `_Stubs` 는 옛 함수만 갈아끼우고 있었다. 로컬 카드 폴더 상태에 따라 테스트 결과가 달라질 수 있었다 — 통과하고 있어서 안 보였다.

## 구간 표제 — 히트가 어느 대목인지 (2026-08-31)

명세: [specs/2026-08-31_segment_title_spec_v5.md](specs/2026-08-31_segment_title_spec_v5.md). 긴 대화는 주제가 여럿인데 이름표가 대화 한 건의 표제뿐이라, **이름표와 요약이 서로 다른 구간을 가리켰다** — 읽는 쪽이 맞는 히트를 버렸고 답은 같은 대화 다른 구간에 있었다 (재질의로 겨우 닿음).

- **조사에서 드러난 것: 구간 제목도 구간 회상어도 처음부터 블록마다 있었다.** 없던 것은 그걸 결과에 싣는 층이다 — 카드 표제 때(v1 §2)와 **같은 진단이 한 층 아래에서 반복**됐다. 그래서 고친 것은 생성이 아니라 표시고, 기존 카드 전량에 소급되며 LLM 비용이 0이다.
- `hits[]` 에 `segment_title`·`segment_turns`·`other_segments`. 앞 둘은 `card_summary` 를 고른 **바로 그 블록**에서 나오므로 이름표와 요약이 어긋날 수 없고, `other_segments` 는 "답이 이 대화 다른 구간에 있다" 를 재질의 없이 보인다 (그 `turns` 를 `read` 에 그대로 넣는다). 구간이 하나뿐인 카드엔 안 싣는다.
- 사서 쪽 정리: 블록 파서를 `card_blocks_for`·`pick_block` 하나로 모으고 카드 파일 읽기를 mtime 캐시로 접었다 (히트당 3회 → 1회).
- 카드 생성은 구간 제목을 「주제 10자」 → 「주제 + 결말 15~25자」로, 회상어는 구간 고유어로. **기존 514장(블록 2개 이상)은 `--segment-titles` 백필이 헤더 제목만 다시 짓는다** — 본문·회상어·턴 범위 불변, 응답이 블록 수와 안 맞으면 통째로 버림(한 줄 밀리면 다른 구간 이름이 붙는다), `# 구간표제:` 표식으로 멱등. **지금이 이 이름을 바꿀 수 있는 마지막 시점이다** — 여태 안 보였으므로 아직 회상의 닻이 아니다(v1 §6).
- 머리줄 처리를 `# ` 전체로 넓혔다. 표식을 하나씩 열거하면 새 표식이 늘 때마다 첫 구간 요약 자리로 샌다 (표제가 v1 §8-1 ②에서 이미 그랬다).
- **곁들여 잡은 것 — `claude -p` 실패 사유가 로그에서 잘려 있었다.** 실패 JSON 은 `is_error`·`usage`·`session_id` 가 앞에 오고 이유는 `result` 에 있는데 stdout 을 앞에서 300자로 자르고 있었다. 이 때문에 이번 백필 실패가 「미로그인」으로 오진될 뻔했다 — 실제 사유는 **`OAuth session expired and could not be refreshed`**(맥 CLI 재로그인 필요, launchd GUI 도메인에서도 동일)였다. 같은 함수가 같은 종류로 사람을 속인 게 두 번째라(2026-08-25 는 stderr 만 찍던 것) 이번엔 형식을 이해하고 읽게 고쳤다.
- 호출 경로 `scripts/com.memex.segment-titles.plist` (card-backfill 과 같은 launchd GUI 도메인 우회).
