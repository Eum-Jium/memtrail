# 카드 표제 — 명세 v1 (2026-08-25)

> 상태: **구현 완료**. 사용자 승인 2026-08-25.
> §7 비용 추정은 **틀렸다** — 실측으로 갱신했다. 근거는 그 절에 남긴다.

---

## 1. 왜

제목은 대화 **초반**에 정해진다. 그런데 회상에 필요한 이름은 대화가 **끝났을 때**
그 대화가 무엇이었는지다. 둘이 벌어진 대화가 1,378건(6턴 이상) 중 **267건(19.4%)** 이다.

| 상태 | 건수 | 뜻 |
|---|---:|---|
| 정상 | 1,111 | 제목 낱말이 본문 전체에 고르게 나온다 |
| 희미 | 110 | 뒤로 갈수록 옅어진다 |
| 초반전용 | 80 | 앞 20% 턴에만 나오고 뒤엔 0회 |
| 무의미 | 77 | 본문과 무관 (「새 채팅」·「콘텐츠로 건너뛰기」 등 자동생성 잔재) |

*(측정: `scratchpad/title_audit.py`. 영문 제목 + 한국어 본문은 낱말이 안 겹쳐
「무의미」로 떨어지므로 267은 **후보군 상한**이다.)*

### 실패 실측 (2026-08-25)

사용자가 「긴 대화 중 결론 못 낸 것」을 물었다. 답에 필요한 대화는 두 건이었다.

| 파일명 | 실제 내용 |
|---|---|
| `<YYYYMMDD>_<자동_제목>.md` | 222턴짜리 <주제 B> 검토 |
| `<YYYY-MM-DD>_콘텐츠로 건너뛰기__gm_<sid8>.md` | <주제 A> 의 방향을 바꾼 결정 |

둘 다 못 찾아서 **본문 낱말 세기**를 직접 돌리고 나서야 나왔다. 그 결과 사용자에게
「그 계획이 <예전 판>인 상태」라고 답했는데, 실제로는 그 뒤 **또 바뀐 상태**였다.
사용자가 "그거 바뀐 거잖아 다시 읽어봐봐" 하고서야 잡혔다. **중간 판을 정본으로 읽은
오답이다.**

## 2. 진단 — 고칠 곳은 생성이 아니라 표시다

카드 헤더는 이미 `## {date} | <주제 (10자 내외)>` 라, LLM 이 내용을 보고 이름을 짓는다.
실물을 열어보면 필요한 말이 **이미 들어 있다**:

```
<날짜>      파일명: 콘텐츠로 건너뛰기
            카드:  ## <도입 주제>                (턴 0-3)
                   ## <중간 검토>                (턴 4-12)
                   ## <주제 A 의 결정>           (턴 13-21)   ← 있다

<날짜>      파일명: <자동 제목>
            회상어: … , <주제 B 를 가리키는 말>                  ← 있다
```

다리 청크 본문에 `[회상어]·[화두]·[주제]` 가 실리므로 **검색은 닿고 있었다.**
그런데 `mailbox_daemon.py` 가 결과에 붙이는 이름표는 파일명 유래 값이다:

```python
"title": meta.get("topic") or Path(sf).stem,      # topic = date_topic_from_stem(파일명)
```

즉 검색이 「<주제 B 를 가리키는 말>」로 정확히 물어와도 화면에는 「<자동 제목>」
으로 뜬다. **읽는 쪽이 맞는 히트를 버린다.** 오늘 실제로 그랬다.

## 3. 층위

| 층 | 무엇 | 지금 | 성격 |
|---|---|---|---|
| 원제 | 파일명. 그때 그렇게 불렸다 | 있음 | **불변** — `conv_key` 정체성 |
| 구간 제목 | 카드 블록별 10자 이름 | 있음 | 잘 돈다. 손대지 않는다 |
| **표제** | 대화 한 건의 이름, **종점 기준** | **없음** | 신설 |

구간 제목이 대표를 못 하는 이유: 「<자동 제목>」의 4블록은 전부 같은
사안이고, 첫 블록은 그 사안의 도입부인데 종점(<최종안>)은
4번째에만 있다. 대화 한 건에 하나의 이름이 따로 필요하다.

## 4. 확정 사항

### 4.1 표제의 꼴 — 주제 + 종결 상태

```
콘텐츠로 건너뛰기        →  <주제 A> 결정 (<결정 내용>)
<자동 제목>              →  <주제 B> 재설계 — <최종안>
사진 정리 스크립트       →  사진 정리 스크립트 — 테스트 직전 중단
독서 습관 만들기         →  독서 목표 — 연간 계획 확정
문서 자동화 실행체계     →  문서 자동화 — 템플릿/배포 구조 확정
```

- **길이 25~35자.** 구간 제목(10자)보다 길다 — 종결 상태를 담아야 한다.
- 종결 상태를 담는 이유는 셋째 줄이다. 「테스트 직전 중단」이 이름에 있으면
  「안 끝난 것 찾기」가 목록 훑기로 끝난다. 오늘 이 조사에 두 시간이 들었다.
- 미결/보류 줄과 중복되는 것은 **의도한 중복**이다. 미결 줄은 *무엇이* 남았는지,
  표제는 *이 대화가 어떻게 끝났는지*다. 전자는 항목, 후자는 이름이다.

### 4.2 범위 — 전량 2,094장

267건만 하면 표제 있는 카드와 없는 카드가 오래 섞인다. 그리고 표제는 나쁜 제목을
고치는 보수 작업이 아니라 **새 층**이다 — 제목이 멀쩡한 대화도 종점 이름은 다르다
(「문서 자동화 실행체계」→「템플릿/배포 구조 확정」).

### 4.3 만드는 법 — 원문을 다시 읽지 않는다

카드 프롬프트가 이미 정한 원칙을 따른다 (`build_memory_cards.py:107`):

> 원문을 안 봐도 이해되게 쓴다. **카드가 본체, 원문은 보험.**

입력은 카드 파일 하나(11줄 × 블록수 ≈ 600자)다. 원문 수백 KB 가 아니다.

### 4.4 파일명은 바꾸지 않는다

개명안(A)은 기각한다. 개명 후보 267건 중 **191건이 파일명에 sid 가 없어**
`conv_key` 가 `date:YYYYMMDD|slug(제목)` 이다. 개명하면 정체성이 바뀌어 dedupe 가
새 대화로 본다 — 2026-08-20 사용자 피드백 1번(중복 문서가 검색 슬롯을 먹는 문제)이
그대로 재발한다. 게다가 정본 파일명을 검색 편의로 고치는 것은
「정본은 원문 대화뿐」이라는 원칙과 어긋난다.

부수 효과로, 파일명이 안 움직이니 `conv_key` 도 안 움직이고 따라서
**mailbox_spec_v3 의 `latest` 트랙 dedupe 와 맞물리지 않는다.**

## 6. 안정성 — 표제는 흔들리면 안 된다

카드는 재생성된다(재요약·구간 재분할). LLM 이 매번 조금씩 다른 이름을 내면
사용자가 「백업 전환 결정」으로 기억하는 것이 다음 달엔 「홈서버 이전 정리」가 된다.
**회상의 닻이 움직이면 회상이 어긋난다.**

- 표제는 한 번 정해지면 **고정**한다. 카드가 재생성돼도 기존 표제를 유지한다.
- **블록 수가 늘어난 경우에만** 재산출한다 (대화가 실제로 이어져 길어진 것).
- 바뀌면 canon 관례를 따른다 — 옛 표제에 취소선을 긋고 아래 줄에 새 표제를 적는다.
  지우지 않는다.

## 7. 비용 — 추정이 틀렸다

추정을 **두 번** 냈고 **두 번 다 틀렸다.** 그 경위 자체가 이 절의 요점이다.

**1차 추정 $10~20** — "입력이 원문 수백 KB 가 아니라 카드 ~600자이니 싸다".

**2차, 3장 실측 → $121 로 상향:**

```
토큰  신규입력 9 / 캐시읽기 0 / 캐시쓰기 83,419 / 출력 114
비용  $0.17 (호출당 $0.0576) — 캐시쓰기 비중 100%
```

여기서 "캐시쓰기가 100%니 호출당 비용이 고정이고, 입력 크기는 무의미하다" 고
결론냈다. **표본 3개로 낸 결론이었고 틀렸다.**

**3차, 1,136회 실측 (진짜 값):**

```
토큰  신규입력 3,405 / 캐시읽기 25,063,652 / 캐시쓰기 4,382,694 / 출력 37,744
비용  $12.43 (호출당 $0.0109) — 캐시쓰기 비중 15%
```

**캐시읽기가 2,506만 토큰이다.** 3장 표본에서 캐시읽기가 0 이었던 건 CLI 시스템
프롬프트 캐시가 아직 안 데워졌기 때문이지, 재사용이 안 되는 게 아니었다.
규모가 붙으면 캐시가 걸려 호출당 $0.0576 → **$0.0109 로 5배 떨어진다.**

- **실측 $0.0109/장 → 2,094장 ≈ $23.** 1차 추정이 오히려 가까웠다.
- 청구액이 아니다 — 구독 호출이라 드는 것은 **사용량(5시간·주간 한도)** 이다.
- **한도에 실제로 걸렸다** — 1,136회에서 `_CLAUDE_DOWN` 이 서고 961장이 미처리로
  남았다. 병렬 8이라 대기 중이던 것들이 한꺼번에 되돌아와 로그엔 한 줄로 뭉쳐
  찍힌다. 시간이 지난 뒤 다시 부르면 남은 것만 이어서 채운다 (표제 있는 카드는
  건너뛴다). **한 번에 끝난다고 가정하지 말 것.**
- `MAX_THINKING_TOKENS=0` 유지 (백필에서 검증됨 — 품질 동일, 8배 빠름)
- 스텁 방어를 그대로 쓴다: LLM 실패 시 표제 줄을 **쓰지 않는다.**
  빈 표제가 붙으면 폴백이 죽어 파일명조차 안 뜬다.

**남길 교훈 둘.**

1. **소표본으로 단가를 재지 말 것.** 캐시가 안 데워진 첫 몇 호출은 정상 상태가
   아니다. 3장으로 잰 값이 실제의 5배였고, 그 숫자로 사용자에게 "$121" 을
   보고했다. 규모가 다른 두 값 사이에서 방향을 잡을 땐 최소 수십 회를 돌린다.
2. 그럼에도 **줄일 것은 입력이 아니다.** 신규입력은 여전히 3,405토큰(호출당 3개)
   뿐이고 비용의 실체는 캐시 트래픽이다. 싸게 하려면 호출 수를 줄이거나 CLI 를
   벗어나야 한다 (직접 API 면 장당 $0.001 미만이나, 2026-08-25 현재
   `ANTHROPIC_API_KEY` 가 리포·데이터 폴더 어디에도 없어 닫혀 있다).

## 8-1. 구현에서 드러난 것 (설계에 없던 것)

**① 원문 청크에는 표제 메타가 없다.** 다리 청크에만 `card_title` 이 실리는데
히트의 **대부분은 원문 청크**다. 메타만 보면 정작 흔한 경로에서 이름표가 파일명인
채로 남는다 — 고치려던 문제가 그대로 남을 뻔했다. `card_title_for()` 가
`card_summary_for()` 와 같은 자리(카드 파일)를 읽어 메운다.

**② `card_summary_for` 가 표제를 요약으로 내보낼 뻔했다.** 그 함수는 헤더 없이
시작하는 카드를 받아주려고 첫 비어있지 않은 줄을 본문으로 삼는다. `# 표제:` 줄이
바로 그 자리라, 회상 결과의 `card_summary` 가 **표제의 복사본**이 될 뻔했다.
`_is_title_line()` 으로 거른다.

**③ 표제 이력은 한 판만 남기면 샌다.** 표제가 두 번 바뀌면 첫 이름이 조용히
사라진다. 「옛 판 보존」은 마지막 판만이 아니다 — 갱신 시 지난 `# 옛 표제(…)`
줄을 전부 이고 간다.

**④ 지문의 하위호환이 이관 비용을 좌우한다.** `card_signature(blocks, "")` 가
표제 도입 전과 **같은 값**이어야 한다. 안 그러면 아직 표제를 못 받은 카드
전부가 지문 변경으로 판정돼 이관 도중 공연히 다시 임베딩된다.

완료·테스트 대기」**. 이 절이 존재하는 이유가 저 「테스트 대기」 다섯 글자다.

**검수 자체가 조사에서 놓친 것을 잡았다.** 한 히트의 표제가
「<사안 셋을 묶은 결정 표제>」였고,
요약에 **"<결정 A> → <결정 B> 로 재설정"** 이 있었다.
같은 날 사람이 본문 낱말을 세어 가며 두 시간 걸려 못 찾은 사실이다.
표제가 붙은 첫 질의에서 나왔다.
