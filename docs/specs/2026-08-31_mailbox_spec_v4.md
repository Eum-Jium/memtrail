# memex 우편함 명세 v4 — 답장 운반 (2026-08-31)

[v3](2026-08-25_mailbox_spec_v3.md) 에 대한 **증분 명세**다. 검색·계보·latest 트랙·trail
프로토콜은 그대로다. 여기서 다루는 것은 **답장이 클라이언트까지 어떻게 실려 가는가** —
검색 품질이 아니라 운반이다. 전부 하위호환이다: v3 형식 그대로 보낸 편지는 같은 답을
받고, 응답에 필드가 하나(`eom`) 늘고 기본값 둘(read 구간·timeline 상한)이 줄 뿐이다.

근거는 claude.ai 실사용 왕복(2026-08-31, 검색 4·read 3·영수증 3)이다.

> **회상 품질은 좋았는데 답장이 운반 중에 깨졌다.** 커넥터 `download_file_content` 는
> base64 를 돌려주고, 모델은 그 문자열을 코드로 **옮겨 적어** 디코드해야 한다. 이
> 옮겨 적기가 길이에 비례해 깨진다 — 6.5~11.9KB 답장 6건은 전부 정상, 18,226B(read
> 13턴)·20,915B(genealogy 55건) 는 base64 문자 수가 4의 배수에서 어긋나 재정렬
> 디코더로 겨우 읽었다. 경계는 12~15KB. 로컬(Claude Code)은 파일 직독이라 무관 —
> **커넥터 경로(claude.ai·모바일·Cowork) 전용 문제**다.

## 1. 답장 수신 — base64 폐지, `read_file_content` 로

해법은 데몬이 아니라 **읽는 손**에 있었다. 커넥터 `read_file_content` 가 (문서화된
지원 목록 밖인데도) `application/json`·`text/plain` 을 텍스트로 바로 돌려준다 — 스킬
구판의 "json 미지원" 메모는 낡은 정보였다. 실측:

| 파일 | 크기 | 결과 |
|---|---|---|
| 실제 답장 `a_…e7s3.json` (genealogy 55건 — **깨졌던 그 답장**) | 20,915B | **무손실 전량 수신** |
| 합성 답장 JSON (블록 20개 + 종결 표지) | 18,135B | 무손실 전량 수신 |
| 원문 md (claude 웹 대화) | 21,030B | 꼬리 ~85자 유실 |
| 원문 md (code 세션) | 65,095B | 꼬리 ~178자 유실 + 이모지 깨짐(👤→ð¤) |

- **스킬 §3 은 `read_file_content(fileId)` 로 바꾼다.** 답장 파일은 그대로 `.json` 이다
  — 데몬·rclone 폴백·아카이브 경로는 아무것도 안 바뀐다.
- 수신문에는 `\_` `\[` 같은 **마크다운 이스케이프**가 붙는다 — 값을 읽는 데 지장 없다.
- **md 꼬리 유실**은 JSON 에선 관측되지 않았지만, 없다고 증명된 것도 아니다. 그래서
  §3 의 종결 표지와 §2 의 예산이 같이 간다 (벨트와 멜빵).

## 2. 답장 크기 예산 — 검증된 크기 안에서만 만든다

무손실이 **실측된** 최대는 ~21KB 다. 답장이 그 안에 들도록 만드는 쪽을 기본값으로 한다.

- **read 예산: 문자 40K → 바이트 20K** (`turn_reader.read_range(max_bytes=20_000)`).
  문자 예산은 한글 위주 구간에서 3배로 부풀었다(글자당 3B) — 같은 예산이 내용에 따라
  6배 출렁이는 단위였다. 턴 경계 절단·`truncated_at` 의미는 그대로다.
- **read 기본 구간: 10 → 6턴** (`to` 생략 시 `from+5`). 앵커는 한 턴을 가리킨다 —
  기본 10턴은 답장 대부분이 곁가지였다. 상한 40턴은 유지.
- **`truncated_at` + 재요청 = 페이지네이션.** 별도 `next` 토큰을 만들지 않는다 —
  "마지막으로 담은 턴" 이 곧 이어 읽을 좌표라, 상태 없는 프로토콜이 유지된다.
- **genealogy `timeline` 상한: 60 → 25** (앞머리 10 + 양끝 보존 표본은 v3 그대로).
  55건 전량을 실었더니 답장이 20,915B 였는데, 답에 실제로 쓰인 것은 `first_mention`
  과 `hits` 뿐이었다. 건수의 정본은 `matched` 다.

## 3. `eom` 종결 표지 + BMP 밖 문자 이스케이프

데몬의 모든 발신 우편(답장·pending·부본·명령 영수증)은 `serialize_mail` 을 거친다:

```json
{ …, "eom": "끝" }
```

- **`eom` 은 항상 마지막 키다.** 수신문 끝에 이게 안 보이면 꼬리가 잘린 것 — 클라이언트는
  `download_file_content`(base64) 로 같은 파일을 한 번 더 받아 보완한다. 중요한 필드
  (query_id·status·first_mention·hits)는 어차피 앞쪽에 있으므로, 잘려도 대부분 읽힌다.
- **BMP 밖 문자(이모지 등 4바이트 UTF-8)는 `👤` 서로게이트 쌍으로 이스케이프**
  한다. 커넥터 읽기가 이 문자들을 깨뜨리는 것이 실측됐고(👤→ð¤), JSON 표준 표기라
  어느 파서든 원문자로 복원한다. 한글·한자(BMP)는 그대로 둔다 — 답장은 사람이 읽는
  좌표다.

## 4. trail 부본 — `edge_candidates`

영수증의 `edges` 는 "이번 대화에서 명시적으로 확인된 관계만" 이라는 원칙 때문에 실사용
에서 늘 비어 온다 (2026-08-31: 3건 모두 공란). 원칙은 옳으니 원칙을 늦추는 대신,
**사서가 후보를 마중 나간다**: used 에 문서가 둘 이상이고 그 사이에 edge 가 없으면
부본에 싣는다.

```json
{"status":"applied", …,
 "edge_candidates":[{"pair":["A.md","B.md"]}],
 "edge_candidates_note":"같은 답에 함께 쓰인 문서 쌍이다. …"}
```

- **제안이지 적립이 아니다.** trail_state 는 안 바뀐다. 이후 회상에서 그 관계가 사용자
  발화로 확인되면 클라이언트가 그때의 영수증 `edges` 로 넣는다 — 추측으로 잇지 않는다는
  §2-1 원칙은 그대로다.
- 이미 edge 가 있는 쌍(방향·relation 불문)은 다시 제안하지 않는다. 최대 5쌍.

## 5. `cowork` 소스 라벨 — 뜻 정정 + 교차 표면 접기

이건 우편함이 아니라 **수집** 층이지만, 검색 결과에 드러나는 문제라 여기 같이 적는다.

- **`cowork` = 데스크톱 앱 기본 탭("채팅 및 Cowork")에서 열린 세션.** 일의 종류가
  아니라 열린 자리다 — 8/29~30 cw 세션 4건이 전부 Code 작업 내용이었다. 과거 대화의
  "Cowork(위임 작업) 사용" 여부를 이 라벨로 판단하면 안 된다 (스킬 §1 에 명시).
- **같은 세션이 두 벌 들어온다**: 로컬 JSONL(`__cc_<uuid8>`)과 클라우드 반출
  (`__cw_<cse8>`)의 세션 id 가 서로 달라 conv_key 로 안 접힌다 (실측: 8/29 binder
  번역 세션 두 벌 — 둘 다 같은 "승인했어 다시해봐" 턴 보유).
- 접기 규칙은 `scripts/surface_fold.py` 단일 소스다. **제목이 아니라 발화 흐름**으로
  판정한다 (cc 파일명엔 프로젝트 슬러그가 붙어 같은 세션도 제목이 안 맞는다):
  ① 첫 두 사용자 발화 슬러그가 접두로 맞물린다 (합쳐 ≥20자) ② 짧은 쪽의 마지막
  발화가 긴 쪽 어딘가에 있다 — 같은 첫 발화로 **다시 시작한 별개 세션**(재시도)을
  안 접기 위한 관문. 판정이 안 서면 접지 않는다 (중복은 남아도 보이지만, 잘못 접으면
  대화가 사라진다).
- **keeper 는 cc** (로컬 JSONL 이 원본 계열 — 발화 시각 보존, archive 동결). 헤더에
  `- surfaces: code, cowork` 와 `- cowork_id: cse_…` 를 남긴다. 전자는 열린 자리의
  기록, 후자는 다음 클라우드 반출이 같은 세션을 다시 만들지 않게 하는 열쇠다.
- 적용 지점 셋: `convert_cowork_sessions.py`(수집 시점 예방 — cw md 를 만들지 않고
  주석만), `dedupe_sessions.py`(이미 들어온 중복 정리 — ③ 교차 표면 패스),
  `unpack_claude_code_jsonl.py`(--refresh 재렌더에서 주석 보존 — carry_annotations).
- 주석은 헤더에만 있고 mtime 을 보존한다 — 턴 번호·청크·카드 생성에 영향이 없다.
